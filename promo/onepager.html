它治的病 为什么你已有的保障可能是零

每一份保障声明都在许同一个诺：「这里要是坏了，我会告诉你。」这个诺言可以检验 —— 而几乎没人检验它。

门禁恒绿 —— 从没见过它红，包括缺陷上线那一次
测试永远通过 —— 因为它从未被观察到失败
策略默认放行 —— 跳过不计数，不计入退出码
证据没人重算 —— 文件在，结论没人复算过
文档写着代码里没有的防线 —— 那句话读起来像保障，实际不存在
共同点：它们都看起来像保障，实际产出为零。而沉默是最贵的输出 —— 因为它和成功长得一模一样。

核心主张 三句话就能讲完

01

先化验你的仪器

所有质量方法都在化验被测对象；试真法第一件事是化验测量用的那台仪器。拿金属在石头上划一道 —— 看那道划痕对不对。

02

每个"没问题"都要配对照

把它要防的东西故意弄坏，它必须红。从没红过的检查，无法证明它能红。

03

缺失必须吵

该有的东西没有时，必须走非零退出。被记成一行日志、一个跳过、一个"待办"的缺失，永远不会响。

五条判据 对着任何保障物件跑一遍 —— 门禁 / 测试 / 策略 / 证据 / 文档 / 一句声明

判据要问的那句话
T0 前置步先查，再造动手前先查有没有现成方案 —— 检索词要像仓库名；排序后必须看最近提交时间；用检索词阶梯并记录是哪一条命中的。
T1 反照负面结论要配正面证据把它要防的东西弄坏，它会不会红？从没红过的检查，无法证明它能红。
T2 落码缺失要走失败信道该有的东西没有时，调用方读到的是什么？答不出"失败"的，就是装饰。
T3 审据验收标准本身要被检什么都不满足时，这条判据会不会也通过？会，那就是尺子错了，不是输入错了。
T4 兑现描述即声明注释 / docstring 声称的行为，要么测它，要么删它 —— 没有第三条路。
T5 辨身代理指标不是判断你用哪个便宜数字代替了决定？它和那个决定在什么情况下会不一致？

两条最贵的推论 都是踩出来的，不是想出来的

跑通 ≠ 报对

产物是对的，打印出来的数是错的 —— 而被读走的是那个数。任何一个被展示的值，都要有自己独立的核验路径。

缺失必须吵

沉默是最贵的输出，因为它和成功长得一模一样。抑制与跳过不是"容忍"，是门禁上的洞 —— 必须计数并上报。

怎么装 三条路径，按需要选

1

读教义（零依赖，先看懂再动手）

仓库里是「为什么这五条成立」和「什么能推翻它」，还有一个给 AI 读的骨架文件。

git clone https://github.com/zhaoxinghua09-cell/assayance
# 人类读 README.md ｜ AI 读 llms.txt
2

跑仓里自带的自检器（这条最能说明问题）

教义必须能检查它自己 —— 仓里那个自检器，就是拿这五条判据量它自己的。先让它失败给你看，再信它。

cd assayance
python tools/check-doctrine.py --selftest   # 先证明它真的会报错
python tools/check-doctrine.py              # 再对真实文件跑
3

当清单用（不装任何东西）

把五条判据贴进你的评审模板、PR 检查项、Code Review 清单。十分钟能跑完一轮。

# 10 分钟自检
1. 列出你依赖的全部保障物件（门禁/测试/策略/徽章/证据文件）
2. 逐个弄坏它要防的东西 —— 它红了吗？   (T1)
3. 每个必需输入缺失时，失败信道里有东西吗？ (T2)
4. 每个阈值：什么都不满足时会不会也通过？ (T3)
5. grep 文档里的"必要性"声明，挑一条弄坏它 (T4)
6. 挑一个你上报的指标，找一个它和决定不一致的场景 (T5)

适用于哪些模型 答案可能和你预期的不一样

试真法不调用任何模型，也不挑模型 —— 它约束的对象是「保障声明」，不是模型。所以它的兼容面比一个 prompt 工具宽得多。

环境支持说明
任意 LLM / AgentClaude · GPT · Gemini · DeepSeek · Qwen · GLM · Kimi …✅ 完全支持五条判据与模型无关，可作为评审清单交给任何 agent 执行
本地离线模型Ollama · llama.cpp · vLLM …✅ 完全支持检测器是纯 Python，零 token、零联网，断网可用
完全不接模型纯人工评审✅ 完全支持全部检测器可独立运行；判据本身就是给人用的
非 Python 项目JS / Go / Rust / 配置✅ 判据适用五条判据语言无关；可运行检测器当前以 Python 实现，其余语言需自建
语言 / 平台✅Python 3.9+；Windows / macOS / Linux
它会替你提高模型表现吗❌ 不会它不是 prompt 技巧。它只管一件事：你的保障声明能不能被证伪

边界 写在最显眼处，而不是脚注里

别夸大它 —— 这三条是硬边界

  • 不声称首创。每个零件都是公开的旧东西：可证伪性是波普尔的，对照是实验室的，故意弄坏是变异测试的，器具检定是计量学的，默认拒绝是策略即代码的。这里命名的，是它们收敛成一套用来管"保障声明"本身的规矩这件事。
  • 不是标准，不声称合规。不对应任何法规、框架或规范的符合性。
  • 不承诺任何效果。没有缺陷逃逸率、没有成本节省、没有通过率。这套方法唯一的产物，是一种更强的"不"。
  • 可证伪条件（这也是它的一部分）：若有人能在从未观察过对照失败的情况下，以同样比率抓住同类静默失败 → T1 的必要性受限；若实践中的主要代价是崩溃而非静默通过 → 适用范围比声称的窄；若这五条无法机械化 → 它退化为建议。
